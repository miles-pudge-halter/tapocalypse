# Demo data

`bun run demo [--dir <dataDir>] [--config <file>] [--repo <dir>]` is a maintainer tool that seeds a throwaway Tapocalypse instance with a fictional project, **Acme Shop** (`com.acme.shop.dev`): about 22 finished runs from the last four days across the omp, Claude Code and Codex harnesses (passes, issues, failures, a blocked run, an infra error with its retry, a cancelled run, a derived verdict and a two-device batch), with each run's report (`report.md`) and evidence screenshots (`screenshots/`) stored in its run folder inside the data dir, the way real runs are, over a temporary git repo that holds no artefacts of those runs (`screens/` holds the five fictional app screens used as evidence). The two oldest runs are seeded as legacy runs (`storage: "repo"`) with their report and screenshots under the temp repo's `qa/`, so the legacy read path stays exercised. It is what the README screenshots are taken from. Without `--dir` it writes to a fresh temp directory and never touches your real config or data dir; it refuses to write into a data dir that already has runs. It prints the command to serve the result, for example `TAPOCALYPSE_PORT=4320 TAPOCALYPSE_CONFIG=<config> TAPOCALYPSE_DATA_DIR=<dir> NODE_ENV=production bun src/server.ts`. The Devices page and the New run sheet read real connected devices, so for screenshots the seed script also exports `DEMO_DEVICES` (a Pixel 8 emulator and an iPhone 16 simulator with made-up ids) to stub `/api/devices` in the browser.
