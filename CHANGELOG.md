# Changelog

All notable changes to this project are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/).

## [0.1.0] - Unreleased

First public release.

### Added

- **Team hub.** Run the same app as a read-only hub (`TAPOCALYPSE_MODE=hub` or `tapocalypse serve --hub`, a `Dockerfile` and `compose.hub.yml` with an oauth2-proxy in front) that teammates' machines push finished runs to, so teammates and stakeholders can browse everyone's runs from one URL. Viewers are authenticated by the access proxy or VPN in front (oauth2-proxy, nginx `auth_request` and VPN-only recipes are documented, with how to verify them); writes need a per-machine upload token (`tapocalypse hub token create|list|revoke`, stored as a SHA-256 digest, compared in constant time). Sharing is opt-in per project (`share`, with a `hubKey` derived from the git remote so teammates' projects merge); finished runs upload in the background through an outbox (`<data dir>/hub-outbox.json`) with back-off, resumable per-file uploads, a pause on a rejected token (401) or a hub that needs a newer Tapocalypse (426), and parking of a run id another machine owns (409). `share.hub` (`url`, `screenshots`, `headers`), `hub-credentials.json` (mode 600) and `TAPOCALYPSE_HUB_TOKEN` / `TAPOCALYPSE_HUB_HEADERS` configure a machine; `tapocalypse hub login|status|push|pack|unpublish` operate it (`push --dry-run` and `pack` show exactly what would be sent). Uploads carry the run document, the activity feed, the report and the screenshots as WebP, with home, repo, data and temp paths rewritten and token-shaped secrets masked; raw agent events, transcripts, the agent session, stderr, the run's MCP token and device serials are never uploaded. The hub recomputes regression keys across machines (`hub rekey`), keeps runs for 365 days (`TAPOCALYPSE_HUB_RETENTION_DAYS`), restricts hosts with `TAPOCALYPSE_HUB_HOSTS`, can show the uploader from a proxy header (`TAPOCALYPSE_HUB_IDENTITY_HEADER`), and has a hub doctor. Routes: `/api/hub/v1/*`, `GET /api/health` (now with `mode`), `/api/hub/status` and the other laptop routes ([API](docs/api.md#team-hub)). Guide: [docs/hub.md](docs/hub.md).
- **Live progress on the team hub.** While a run of a shared project is in progress, the laptop sends its status and checks (redacted like an upload, no screen, activity or screenshots) to `PUT /api/hub/v1/runs/:id/live`: on every change (at most every 3 s per run) and every minute. Hub viewers see it in the run lists, a *Running now* list on Home and Overview, and on the run page (*Live from `<machine>`*, amber after 3 minutes without an update); the finished upload replaces it without a reload. The hub keeps live runs in memory only (dropped after 30 minutes of silence, at most 32 per machine and 512 per hub), so stats, overview, releases, regressions and retention never see them. A refused live update never pauses uploads. `share.hub.live: false` turns it off on a laptop.
- **Project overview and Releases.** A stakeholder landing page per project (pass-rate trend, latest result per test and platform, newly failing and flaky counts, what changed since the last release) and a release view (a version or a `release/*`, `releases/*`, `hotfix/*`, `release-*` branch across every machine: blockers first, BLOCKED counted as could-not-test, a tests × devices matrix, changes against the previous release), in the app on a laptop and on a hub. `GET /api/projects/:id/refs`, `/overview` and `/releases/:kind/:name`; `GET /api/runs` gains `version` and `machine` filters, and `/api/stats` day buckets gain `issues` and `other`.
- **Faster regression index at scale.** The index builds oldest first; at 50,000 runs the first regression query dropped from about 16 s to about 2 s. Tapocalypse now requires Bun 1.3.14 or newer (`Bun.Image` re-encodes uploaded screenshots).
- **Shareable single-file reports.** A finished run can be turned into one self-contained HTML document (verdict, run facts, summary, checks table, sanitized report and every screenshot inlined as `data:` URIs, no scripts or external requests, light and dark, printable, readable at phone width; at most 25 MB of images, the rest shown as "screenshot omitted"): **Share → Download HTML report** on the run page and the report page, `GET /api/runs/:id/report.html[?download=1]`, `tapocalypse report <id> --html <file>` and `qa_share_report`. With the new optional `share.s3` config (`bucket`, `endpoint`, `region`, `prefix`, `expiresInDays` 1-7), **Share → Copy share link**, `POST /api/runs/:id/share`, `GET /api/share/status`, `tapocalypse share <id>` and `qa_share_report` upload the file to a private S3-compatible bucket (S3, R2, MinIO) and return a presigned link; anyone holding the link can open the report until it expires. Credentials come only from the environment (`S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` or the `AWS_*` pair), never from the config file. Sharing is disabled while a run is active.
- **Regression intelligence.** Every check gets a persisted identity across runs, and runs are compared with an automatic baseline. Runs now carry `testKey` (the recurring test: suite id, parent, brief or run title) and `checkHints`, checks carry `checkKey`, `keyKind` (`suite`, `lineage`, `carried`, `title`, `inferred`, `manual`), `keyScore` and `was`, all additive and assigned once a run reaches a final state (older runs are keyed at the first start after the upgrade). The agent is shown the checks of the test's last two runs, without their statuses, and links a check to one with `was` in `qa_plan`; `reuseChecks: false` on `POST /api/runs`, `POST /api/batches`, `qa_start_run` and `qa_start_batch` opts out, and re-runs now read their branch, commit and uncommitted state from the project at queue time. The baseline is the newest earlier run of the same test and platform on the PR's base branch, the default branch (new optional `Project.defaultBranch`, else `origin/HEAD`, else `main`/`master`), the same branch, or any branch, folding round-1 and round-2 runs at one commit; transitions are *newly failing*, *fixed*, *still failing*, *changed* (with *lost coverage*), *new*, *removed* and *flaky*, where only pass and fail are decisive. Checks that flip between pass and fail on the same code and device are *flaky* (2 flips) or *suspect* (1) and are kept out of the regression counts; a pass on one device and a fail on another is shown as *device-sensitive*. New: `GET /api/runs/:id/compare`, `/baseline-candidates`, `/api/runs/:id/checks/:checkId/history`, `/api/projects/:id/checks/:checkKey/history`, `/api/projects/:id/flaky`, `POST`/`DELETE /api/check-links` to confirm or unlink a match, `regressed=1` on `GET /api/runs` and a `regression` summary on finished runs; MCP tools `qa_find_regressions`, `qa_compare_runs` and `qa_check_history`; CLI `tapocalypse compare` and `tapocalypse run --fail-on regression`, plus baseline properties and `Newly failing` / `Flaky` messages in the JUnit report; in the UI a *Compared to* strip, per-check badges, a compare page with side-by-side, swipe and onion-skin screenshots, a check history sheet, a regressions chip and filter in the runs list, and a Flaky checks page. History is computed in memory from the stored runs.
- **Device leases: Tapocalypse is the device broker.** Coding agents on the machine borrow an emulator or simulator with the MCP tools `device_acquire`, `device_renew` and `device_release` (or `POST /api/leases`, `/api/leases/renew`, `/api/leases/release`), so two agents, or an agent and a QA run, never drive one device at once. A lease has a holder, a reason and a TTL (default 30 min, 5-120) that renewing extends; waiting agents and queued runs share one first-in, first-out queue with tickets (`waitSeconds` up to 110), and `device_acquire { platform }` boots a configured emulator or simulator when none is free. Agent leases survive a restart (`<data dir>/leases.json`, owner-only); the secret `leaseId` never appears in lists, events or the UI. `qa_list_devices` and `GET /api/devices` show each device's `lease` and `waiters`, `GET /api/events` emits `lease` events, `GET /api/devices/pool` reports who waits for any device of a platform, and queued runs say which agent they wait for (`queueHold`, `<serial> is held by <holder> until HH:MM`). The Devices page shows holder, reason and time left on held devices, with **Release…** for a stuck lease, a bell to be notified when a device frees up, and live counts in the pool header, the live strip and the sidebar; the New run picker disables held devices. Leases are cooperative (raw `adb` bypasses them); a device that is leased is never idle-shut down and cannot be shut down from the UI. See [Sharing devices between agents](docs/guide.md#sharing-devices-between-agents) and the instructions snippet in [docs/agent-setup.md](docs/agent-setup.md#8-let-your-agents-borrow-devices-optional).
- **QA runs drive their device through the gateway.** The run endpoint `POST /mcp/runs/<id>` serves the same `mobile_*` tools pinned to the run's device (no `device` argument), instead of mounting a mobile-mcp into every agent session: Claude Code, Codex CLI and omp (through a per-run plugin dir `<run>/plugin/tpc` running the stdio bridge, replacing the mobile-mcp plugin and the detection of the user's omp MCP config) all get only the `tpc` server. Adapters keep canonical `mcp__mobile_mcp_mobile_*` tool names for the feed, and a mobile-mcp the agent mounted itself is flagged as a backend violation.
- **Old runs keep replaying cleanly.** Runs now record `gated: true` (additive; older `run.json` files load as `false`) when the agent is spawned with its device tools from the gateway. Only gated runs flag an agent's own `mobile_mcp` tool as a backend violation, so the activity feed of a run recorded before the gateway, where Tapocalypse itself mounted mobile-mcp, shows those calls as ordinary tool rows. Tapocalypse's own run-management server is flagged on every run, and a Claude Code plugin-namespaced one too.
- **A run never starts an agent without device tools.** Before the harness is spawned, the runner makes sure the gateway serves device tools (warming it if needed, so the agent's first listing is answered from memory; omp would otherwise drop the server) and otherwise ends the run as a retried `infra` failure ("device tools unavailable: …" with the probe's error) instead of paying for a turn that cannot drive the device. omp no longer trusts its provisioned plugin when its prompt bounds the MCP route list: a bridge it cannot confirm within the wait counts as not connected.
- **Device gateway: Tapocalypse's `mobile_*` tools are lease-gated.** `/mcp` also serves mobile-mcp's 28 device tools (`mobile_take_screenshot`, `mobile_click_on_screen_at_coordinates`, `mobile_batch_commands`, …) under the same names, with `device` replaced by a required `leaseId` from `device_acquire`. Tapocalypse starts one mobile-mcp child per leased device (in the lease's `cwd`), pins every call (every batch step too) to the leased device, renews the lease on each call and stops the child when the lease ends; an unknown or ended `leaseId` is `lease_not_found: <reason>`. Raw `adb`, `xcrun simctl` and an agent's own mobile-mcp server are still not stopped. Device listing and the remote-cloud tools are not offered, tool schemas are read from mobile-mcp and cached in `<data dir>/gateway-tools.json` (the first-ever listing probes mobile-mcp once, up to 15 s), `GET /api/mcp/status` gains `gateway: { tools, mobileMcpVersion }`, `MOBILE_MCP_BIN` swaps the mobile-mcp command, and the Setup prompt and skill tell agents to pass `leaseId` to the `mobile_*` tools instead of using another mobile-mcp server.
- **Brand.** The "Charged T" logo (favicon, sidebar, mobile header, desktop notifications, first-run hero, README) with a warm amber/near-black theme in light and dark mode, JetBrains Mono for ids and code, and small lightning touches: a flickering bolt for running runs, a lightning bolt that runs along the running progress segment, a one-shot flash when a run you are watching reaches its verdict, and a lightning arc that crosses buttons, sidebar items and option cards when you activate them. Warning states moved from amber to orange so they never look like the brand accent. Device frames follow the real device: phone, tablet, watch and TV bodies with the screen's true aspect ratio.
- **Agent harnesses.** The QA agent is no longer tied to omp: a run can use omp, Claude Code (`claude -p`, stream-json) or Codex CLI (`codex exec --json`). Choose one per run (New run picker, `--harness`, `harness` in `POST /api/runs`, `POST /api/batches`, `qa_start_run`, `qa_start_batch` and `qa_rerun`), per project (`agent.harness`), in a persona (`harness:` frontmatter) or in the config (`agent.harness`, `agent.harnesses.<id>` with `bin`, `model`, `effort`, `permissions`, `sandbox`; `agent.maxTurns` and `agent.maxBudgetUsd` for Claude Code); `CLAUDE_BIN` and `CODEX_BIN` join `OMP_BIN`. Without a choice the first harness that is installed and signed in is used, else the first installed, else omp, and runs and `run.json` files from before this change count as omp. Model and effort strings are harness-native, and a persona's `model:` applies only to its own harness. Doctor reports every installed harness (install and sign-in) plus an `agent-runtime` check that needs at least one; `GET /api/harnesses` lists them with their capabilities and `GET /api/models?harness=` lists models per harness. The run page shows the harness, hides the steer box and Transcript button when it cannot steer or export one (Codex CLI cannot steer; transcripts are omp-only). Turn and budget limits end a run as `errorKind: timeout` with the limit named, and the verdict is derived as for a time-out.
- **Run progress endpoint.** Agents report `qa_plan`, `qa_check` and `qa_finish` to `POST /mcp/runs/<id>` (server `tpc`, a random bearer token per run, passed to Claude Code in an owner-only `mcp.json` and to Codex CLI as an owner-only `tpc-mcp.json` read by a stdio bridge (`src/mcp/stdio-bridge.ts`, so it works on every Codex version, including those without HTTP MCP support), both in the run's data folder, never on the command line or in the environment); omp keeps its native host tools and needs no token. Both feed one recorder.
- **Runs.** Start parallel QA runs from the web UI, the CLI, plain HTTP or MCP: a project, a free-text brief and a platform or device. Runs queue when every device is busy; configured AVDs and simulators are booted on demand and shut down when idle.
- **Live monitoring.** Per-check progress, live device screen, a rich activity feed (tool calls paired with their results), steering and cancelling mid-run, and a summary of cost, tokens and tool calls per run.
- **Batches.** Fan one brief out to several devices (`POST /api/batches`, `qa_start_batch`, `tapocalypse run --devices N`); a batch rolls its runs up into one verdict and cost.
- **Re-run failed or all checks** of a run, with the previous status and notes passed to the agent.
- **Suites.** Saved, repeatable briefs with fixed check ids in `<repo>/.tapocalypse/suites/`, and built-in brief templates (smoke, regression, ticket verification, accessibility, offline and poor network, first run).
- **Reliability.** Time budget given to the agent (`runMaxTime` must be a valid duration, checked at startup) and a reminder at 80% of it; a hard kill at the budget for Claude Code and Codex CLI and 5 minutes after it for omp, which enforces `--max-time` itself; a derived verdict when the agent stops without reporting one; classified errors (infra, agent, timeout, cancelled); one automatic retry for infrastructure failures; installing an APK or app bundle before a run.
- **CLI and CI.** `tapocalypse serve | service | doctor | run | status | report`, with `--wait`, JSON output, JUnit XML and verdict-based exit codes for CI.
- **MCP.** Tools to list projects, devices and suites, start single runs and batches, wait on one or many runs, steer, cancel, re-run, and read reports and screenshots.
- **Run metadata.** Branch, commit, pull request, tickets, labels and app build recorded per run and searchable.
- **Reports.** Per-project markdown reports with a table of contents, a link back to the run and a screenshot gallery; report HTML is sanitized.
- **Artefacts live in Tapocalypse, not in your repo.** A run's report and screenshots are stored in `<data dir>/runs/<run-id>/` (`report.md`, `screenshots/`); the agent is told never to write into your repository and a QA run leaves your working tree clean. The agent hands them over through the progress tools: `qa_check { screenshot }` takes an absolute or working-directory-relative image (extension and image content are checked, then it is copied in) and `qa_finish { reportMarkdown | reportPath }` takes the report text or a file the agent wrote. Read them with `qa_get_report`, the new `qa_get_screenshots`, `qa_get_run` (absolute `reportPath` / `screenshotsDir`), `tapocalypse report <run-id>`, `GET /api/runs/:id/report` or `GET /api/runs/:id/files/<path>`, and copy them anywhere on demand with `qa_export { runId, dir }`, `tapocalypse report <run-id> --export <dir>` or `POST /api/runs/:id/export`. Files are served only from the run's own folder, images only. Retention and **Delete** remove a run's report and screenshots with the run. In CI, export the report or read it through the API instead of uploading it from the checkout.
- **Compatibility.** Runs from before this change keep loading and rendering from their repo-relative report and screenshot paths. A project's `reportsDir` is now a legacy, read-only setting that only lists those older reports; it is no longer offered by `qa_create_project`, `qa_update_project` or detection, and nothing new is written to it.
- **Background service.** `tapocalypse service install` keeps Tapocalypse running in the background and starts it at login (a launchd agent on macOS, a systemd user unit on Linux); `service status | logs | start | stop | restart | uninstall` manage it. It only touches its own unit and is not supported on Windows. The unreachable-server error now suggests `tapocalypse service start`.
- **Projects.** Detection of Flutter, React Native / Expo, native Android and iOS and Kotlin Multiplatform repositories; folder suggestions when adding a project.
- **Web UI.** Rebuilt as a React 19, Tailwind v4 and shadcn/ui app with a sidebar shell, command palette, dashboard with live strip and filters, run workbench, devices page, setup guide, notifications, and light and dark themes.
- **Platform.** Doctor checks for the agent runtime's install and sign-in and for operating-system support, XDG config and data locations, optional retention of old runs, macOS and Linux support.
- **Devices and queue.** A Devices page with run slots, live thumbnails and per-device state, manual boot and shutdown of configured AVDs and simulators, and a plain-language reason on every queued run. Watches and TVs are never used for QA.
- **Run history.** Delete a finished run from the UI or `DELETE /api/runs/:id`; `retention.days` / `retention.maxRuns` clean up old runs automatically.
- **Security notes per harness.** SECURITY.md lists each harness's no-prompt mode (omp `--auto-approve`, Claude Code `bypassPermissions` or an allowlist, Codex CLI `danger-full-access` with `approval_policy="never"`) and Codex CLI's own trusted-project entry in `~/.codex/config.toml`.
- **Security hardening.** Sanitized report HTML with external images dropped, a Content-Security-Policy and frame protection for the UI, `X-Frame-Options` / `frame-ancestors` on API responses, a 1 MiB request body limit, and Host, Origin and content-type guards.
- **CLI.** `tapocalypse serve --dev` starts Bun's development server with hot reloading.
- **Documentation.** Configuration and HTTP API / MCP references under `docs/`.
- **Open source project files.** Continuous integration, issue and pull request templates, contributing guide and security policy.

### Security

- **Redaction is stricter and also covers share links.** Uploads to a team hub and the standalone HTML report (share link, download, `report --html`, `qa_share_report`) now go through the same redactor: device serials, UDIDs and AVD names become `<device>` (so "device serials are never uploaded" is now true), and the report's title, summary, notes and text lose paths and your account name like an upload. New secret shapes are masked: camelCase names (`accessToken`, `clientSecret`, `secretAccessKey`, `AccountKey`, …) without touching counters such as `maxTokens`, `cookie` / `session` / `sid` names, `Authorization` values of any scheme and `Cookie` headers, `--password` / `--token` / `--secret` / `--api-key` flags, `curl -u user:pass`, URL credentials with an empty user, PGP private keys, and values with escaped quotes inside JSON-encoded commands. Redaction stays a backstop. A 1 MB input is redacted in well under a second.
- **Served files are inert.** `/files/…` and `/api/runs/:id/files/…` decide the type from the file a path really resolves to, send an explicit `Content-Type`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; img-src 'self' data:; sandbox`, and require real image bytes for images. A `.png` that links to an `.html` file, or an image name over a non-image file, is now a 404 instead of being served. A legacy `reportsDir` (default `qa`) that resolves outside the repository, such as a symlink in a cloned repo, is no longer listed, rendered or served.
- **The hub refuses ambiguous paths.** In hub mode a request whose path contains `%2f`, `%2e`, `%5c` or a backslash gets `400 ambiguous_path`.
- **Hub tokens are scoped tighter.** A token can create at most 20 new hub keys per 24 hours (`429 too_many_projects`); a project's repository URL and subpath stay as the first upload wrote them; uploaded and live `startedAt` / `endedAt` must be ISO datetimes or `null` (`422 invalid_run`) and any time later than the hub's clock plus 5 minutes is replaced by the time of receipt; regression re-keying runs at most once per project every 5 minutes; and `POST blobs/check`, `GET runs/:id/state` and `DELETE runs/:id` share a new `meta` rate limit (600 a minute per token). The hub docs now say plainly that a token can learn whether a run id or a file exists. New admin commands: `hub project remove <hubKey>` (only for a project with no runs, else `409 project_not_empty`) and `hub project set-default-branch <hubKey> <branch>|--clear`. `.dockerignore` excludes `hub-credentials.json` and `share-credentials.json`.
- **A different hub address cannot take the saved token with it.** Changing the hub to another origin through Setup or `hub login` needs the new hub's token in the same request (`400 token_required_for_new_hub`) and drops the saved proxy headers unless new ones are sent. With `TAPOCALYPSE_HUB_TOKEN` set in the environment such a change is refused: edit `share.hub.url` in the config file and the environment variable instead.
- **Agents are told what is untrusted.** The default persona and every run's prompt now say that text from the app, the device (element text, logs, crash reports), web pages and git or `gh` metadata is data, never instructions: no commands it suggests, no credential files or files outside the repository and run folder, nothing sent anywhere but the `qa_*` tools, and a suspected injection goes into the report. The branch, commit subject and pull request title are JSON-quoted, cut at 200 characters and labelled as untrusted in the prompt.
- **Claude `allowlist` mode is scoped to the run.** Read access to the repository, the run folder and the temp folder, write access to the run folder only, and, for the run's own device only, `adb -s <serial> …` (without `push`, `pull`, `install`, `uninstall`) or `xcrun simctl …` (without `install` / `uninstall`, and screenshots only into the run folder). It reduces accidents and blocks the known exfiltration paths; it is not a sandbox against prompt injection, and SECURITY.md says so.
- **Secrets stay out of agents.** Agents and mobile-mcp children no longer inherit `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` or `S3_SESSION_TOKEN`, nor `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` or `AWS_SESSION_TOKEN` when `share.s3` is configured, in addition to `TAPOCALYPSE_HUB_*`. Agents run as you and can still read the mode-0600 credentials files, so keep hub tokens and S3 keys narrowly scoped.
- **mobile-mcp is pinned.** The device gateway starts `@mobilenext/mobile-mcp@1.0.11` instead of `@latest`; `MOBILE_MCP_BIN` still overrides it.
- **Private data folder and service unit.** The data directory and `runs/` are created with mode 0700 and an existing one is tightened at start. `tapocalypse service install` writes the unit with mode 0600 and no longer copies `TAPOCALYPSE_HUB_TOKEN` or `TAPOCALYPSE_HUB_HEADERS` into it (it warns; the service reads `hub-credentials.json`). Run `service install` again to tighten an existing unit.
- **Supply chain.** GitHub Actions are pinned by commit SHA, and the Dockerfile base image, nginx (now the 1.30 line) and oauth2-proxy in `compose.hub.yml` by image digest, with the tag kept for reading. Dependabot also watches the Dockerfile and the compose file. `postcss-selector-parser` is pinned to 7.1.6 with a `package.json` override to fix its advisory.
